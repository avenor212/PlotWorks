# 个人自定义单线字体：方案盘点

给"想用自己的字迹在纸上写字"的个人用户准备。核心问题是：**写字机需要的是笔画中心线，而市面上几乎所有"手写字体"给的都是轮廓**，两者不能直接换用。

## 为什么不能直接用现成的手写字体

任何 TrueType/OpenType 字体（包括各类"手写体生成器"产出的）存的都是**闭合轮廓**——一个"永"字在字体文件里是十几条围出笔画的细长环。写字机沿轮廓走，每一笔会被描两遍、中间留着空心。

这不是格式转换能解决的：轮廓里没有"这一笔从哪起笔、到哪收笔"的信息。要得到中心线，必须**重新提取**（骨架化），或者**从一开始就画线**。

现有内置字体走的是第二条路——Hershey 字形本身就是折线，汉字走的是 Make Me a Hanzi 的笔画中位线。

## 四条可行路径

### A. 数位板/触控笔直接画线（质量最好）

在能画矢量的软件里，用"画笔/钢笔"工具**一条线画一笔**，不填充、不描边。

- **工具**：Inkscape（免费）、Illustrator、Affinity Designer
- **门槛**：要有数位板；会用钢笔工具
- **质量**：★★★★★ 完全可控，想连笔就连笔
- **速度**：一个字符 10–30 秒，95 个 ASCII 约 1 小时；1000 个汉字约 8–15 小时
- **注意**：必须保证是**开放路径**（不闭合）、每条路径 = 一笔

适合：只想做英文名、签名、少量常用字的人。

### B. 纸笔手写 → 扫描 → 自动骨架化（最像本人字迹）

在白纸上按格子写字（一个字一格），扫描/拍照，然后让软件把轮廓细化成中心线。

- **工具**：Inkscape + `Centerline trace` 扩展（autotrace / potrace 的中心线模式），或专门的骨架化工具
- **门槛**：会用扫描 + 会调 Inkscape 参数
- **质量**：★★★☆☆ 笔画交叉处容易出毛刺、断笔；转角会被圆化；反复调参才能用
- **速度**：采集快（写一页就行），后处理慢（几个字要调半天，几百字基本不可行）
- **致命问题**：汉字笔画密集，骨架化后经常出现"两条笔画粘连成一条"

适合：英文/数字（笔画稀疏，骨架化效果好），汉字不建议。

### C. 已有字体 → 骨架化（最快，但已经不是你的字了）

拿一款现成的手写/楷体字体，逐字渲染成位图，再骨架化。

- **质量**：★★☆☆☆ 字体本身的轮廓信息被丢弃，只剩骨架，粗细对比全失
- **本质**：这等于给现有字体"做了一次降质转换"，得到的东西和直接用内置楷体骨架没有区别
- **结论**：不建议。这条路的价值为零——内置的楷体骨架已经是这个质量了。

### D. 直接写 Hershey 格式（极客向）

`.jhf` 是纯文本，每行一个字符的坐标序列：

```
10 21A 9MWRFRT RFPK...
```

- **门槛**：需要理解格式，手写坐标不现实，通常要写脚本
- **质量**：取决于画的人
- **适合**：能写代码、想批量生成的人

## 现实的结论：按字符集拆开做

**个人做一整套含汉字的单线字体不现实。** 一个汉字采集 + 修整平均 1–2 分钟，3000 字就是 50–100 小时，还没算返工。

真正可行的做法是**按需做子集**：

| 用途 | 字符集 | 采集量 | 可行性 |
|---|---|---|---|
| 英文名字牌、签名 | ASCII 95 个 | 1–2 小时 | ✅ 完全可行 |
| 拼音标注 | ASCII + 带声调字母 | 2 小时 | ✅ 可行 |
| 某个客户的名字 | 3–5 个字 | 10 分钟 | ✅ 非常可行 |
| 生字卡（小学常用字） | 500–800 字 | 10–20 小时 | ⚠️ 需要分多次 |
| 全字库 | 6763 字 | 100+ 小时 | ❌ 不建议个人做 |

对定制工作室、写教案的老师来说，"常用 200–500 字"是个合理的中间点——覆盖了人名的绝大多数用字。

## 应用侧该开什么样的口子

现在的单线字体是**编译进程序**的（`hershey-glyphs.json` + `hanzi-strokes.json`）。要让个人字体进来，需要三件事：

### 1. 数据格式

建议沿用现有结构，一个文件一款字体：

```json
{
  "name": "张三的手写体",
  "unitsPerEm": 1024,
  "baseline": 0,
  "left": 0,
  "right": 1024,
  "glyphs": {
    "65": { "strokes": [[[120,300],[400,300],[400,700]]] },
    "23383": { "strokes": [[[100,200],[500,200]], [[300,200],[300,800]]] }
  }
}
```

- 键是 Unicode 码位（十进制）
- `strokes` 里每个数组是一条**开放折线**，坐标 y 向上、基线为 0
- 缺的字按现在规则处理（汉字缺笔 → 整段回退轮廓）

### 2. 导入方式（两个层次）

**低门槛**：应用里一个「导入字体…」按钮，接受上面那种 JSON。用户在 Inkscape 里画好、用一个小转换脚本导出 JSON。

**高一点**：直接吃 SVG——`<path id="A" d="...">`，`id` 就是字符。设计师不用碰 JSON。代价是应用里要写一个 SVG path → 折线的转换（项目已经有 Svg 解析库，成本可控）。

### 3. 显示问题（唯一的硬骨头）

自定义字体**没有对应的 TTF**，所以画布上的文字没法用你的字迹显示——只能回退到某个系统字体。

三种处理方式：

| 做法 | 效果 | 成本 |
|---|---|---|
| 画布用系统字体，刀路用自定义数据 | 所见非所得（和现在中文一样） | 低 |
| 让用户同时勾一个"用于显示的系统字体名" | 字形接近，但仍是两套 | 低 |
| 导入时把折线**加粗成细条带**，现场生成一个 TTF | 所见即所得 | 高（要内嵌字体生成/加载） |

第三种在技术上是可行的——内置字体本来就是这么做的（`tools/build-hershey-fonts.py` 把折线缓冲成细条带生成 TTF）。但那是离线构建，运行时生成 TTF 并注册进 WPF 需要额外的字体加载机制，工作量不小。

## 建议的第一步

先做**最小可用**：JSON 导入 + 画布用系统字体显示 + 刀路用自定义数据。配一个转换脚本（Inkscape 画好的 SVG → JSON），放在 tools 里。

这样一个人今天下午就能做出"英文名用的手写体"，十分钟内看到自己写的字被机器描出来。

汉字等有人真的需要再说——到那时，骨架化的工作量才是真正的瓶颈，而不是格式。

## 已经准备好的：SVG → JSON 转换脚本

[tools/svg-to-stroke-font.py](tools/svg-to-stroke-font.py) 已经写好并测过。

**用法**：

```bash
python tools/svg-to-stroke-font.py 我的手写.svg 我的手写.json --name "我的手写体"
```

**SVG 里怎么画**：

```xml
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 1000 1000">
  <path id="A"    d="M 100 800 L 300 200 L 500 800"/>
  <path id="A-2"  d="M 170 600 L 430 600"/>
  <path id="中"   d="M 150 300 L 450 300"/>
  <path id="中-2" d="M 300 150 L 300 750"/>
</svg>
```

- `id` 的**第一个字符**就是这个字形，后面的部分随便写（因为 SVG 里 id 不能重复，一个字的几笔要拆成几个 path）
- 一条 path = 一笔，不要闭合
- 曲线要先用 Inkscape 的「扩展 → 修改路径 → 压平贝塞尔曲线」转成直线

**脚本会做**：

- 把 svg 的 y 翻成表里的 y 向上、基线 0
- 用 RDP 简化（默认容差 1 个 svg 单位，`--simplify 0` 关闭）
- 基线默认取所有路径的最低点，可以用 `--baseline` 指定

**实测输出**：

```
wrote testfont.json
  characters: 3
  points:     12
  baseline (svg y): 800.0
```

三个字符（A 两笔、L 一笔、中两笔），坐标正确：A 的顶点在 y=600，L 收在基线 0。

**还没做**：应用侧的「导入字体」按钮。需要先定两件事——

1. 导入后画布上怎么显示（系统字体糊弄，还是现场生成细线 TTF）
2. 字体从哪里加载（`%LOCALAPPDATA%\IridiumIO\PolyCut\Fonts\*.json` 自动扫描，还是每次手动选文件）
